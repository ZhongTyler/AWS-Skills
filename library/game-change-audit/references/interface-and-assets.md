# 界面与资源审查

## 从交付用途进入

识别当前产物是单体PNG、静态组合、真实控件预览、引擎运行还是交付包。读取宿主已定的布局、艺术方向、目标视口、支持输入及状态矩阵。沿既有catalog核对ID、来源、许可、版本和实际消费者，缺失项保持未知。

冻结本次受影响资源清单。逐项审查约定范围的实际图片与状态，范围大时按风险分批，并显式保留未看项。图板、缩略图、页面“可加载”或数量相符只支持对应检查，不能据此勾选逐项视觉通过。

图像较多时按页面或状态分批，每批把已看ID、版本、发现与未覆盖项落到原审阅记录，再继续下一批。图像上下文或时限承压时先收口当前批次。合成清单只提取当前场景的文字、坐标与资源ID，内嵌图像数据沿图片入口查看。完整覆盖与抽检分别记录。

## 单体、组合、真实运行

1. 单体看轮廓、透明边、切图邻接、主体比例、缩放方式和材质完整性。按用途核对正常、悬停、按下、选中、焦点、禁用及告警，检查组合状态冲突。
2. 组合看完整玩家任务。文字与数值对得上图标、单位和路径，标签、箭头及端点齐备，覆盖层保持目标、按钮和关键区域可读。费用、次数、对象和预览与所显示状态相符。
3. 以实际目标尺寸复核。最小窗口、长标签、大数值和不同背景重点看裁切、遮挡、信息主次与语义辨认。缩略图发现疑点后回原尺寸，目标视口和图片缩小预览分别标注。
4. 有运行入口时再验实际输入、焦点与返回、禁用原因、命中范围、动态文字、时序及状态切换。动画检查身份/比例/锚点、接触、遮挡、动作含义和循环接缝；光照、音效与反馈需要真实播放证据。

完整画面出现问题时定位组成关系，区分源图缺陷、裁框/拉伸、布局层级、状态数据、运行消费与当前未实现的连接。需要时读取合成清单或真实控件源码验证，既有矩形无重叠检查覆盖不了图像内部文字和不透明装饰。

## 边界、对齐与叠层

视觉检查以实际画出的边界和内容为准。分别看整页层级、真实显示尺寸和疑点局部，放大图用于定位，缩回目标尺寸再判断可读性。按风险覆盖以下关系。

- 边界与对齐。沿面板装饰框的可见内沿确定内容安全区，核标题、正文、快捷键、页签、图标及按钮的留白与同组左边界、基线和间距。控件矩形位于图片内，仍可能压住木框、斜边或图标自身的装饰；角落按钮和贴底按钮单独看。同一组件复用到不同场景时核对实际容器。
- 标记与信息。字母、序号、数值、勾选、焦点及锁标，在目标尺寸下应能辨认且指向明确。逐对检查标记与单位、血点、路径、范围、徽章和文字的接触或覆盖。已有标记只证明存在；新增标记后复核原身份、状态与操作是否仍看得清。
- 编码与冗余。先问玩家需要区分什么，再选择字母、颜色、形状或连线。字母已足够时可使用一致样式，避免为满足通用建议叠加多套编码。当前用户取舍和已批准例外进入本次判据，旧规范有冲突时同步实际owner裁决。
- 源图与合成。将实际alpha、裁框残片和烘入底色，与渲染器主动绘制的底板、遮罩、透明度和图层顺序分开定位。在深浅及实际背景检查小尺寸成品，必要时查看源PNG和合成数据。修正可见残底前先核来源，避免反复抠透明图却保留绘制底板。
- 状态叠加。按控件用途决定状态标记是替代身份图形还是独立角标，并在禁用、选中、焦点、警告组合中验证。额外底托不能覆盖主要身份或邻近控件；徽章的视觉边界、透明区域与实际可见主体一并核验。

用户反例或新增叠层触发回查时，保留旧评审，重开受影响视觉结论；同组件或同合成规则的其他状态沿根因扩展检查。只复用仍覆盖本问题的旧证据。修后保存前后版本、目标尺寸表现及相邻正常状态，确认问题消失后再回写通过。审查记录分开写看过哪些图、查过哪些关系、哪些结论仍待验证，避免用阅读数量替代审查质量。

## 防止误报

保持已批准的布局、风格、术语和取舍。推断一个按钮错误前检查当前阶段、选中对象、支付规则及动态覆盖。概念稿未表现运行功能时，归入该交付阶段的缺项或待验证项。静态图显示错误可以确认该图的问题，进一步推断生产规则错误需运行证据。

## 返回可处理的问题

使用具体资源ID、文件哈希、状态名和图中区域，说明玩家会看错、找不到或误操作什么。给出相邻正确状态作为反例。技术可用、视觉自审、制作人采用及引擎接入各有独立依据。同步审查时先固定快照，再与owner已有发现和修后版本去重，才能判断本方法带来的实际增量。
