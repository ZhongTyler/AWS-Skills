# 效果校准

审查方法能否安装、发现问题和相对原流程有无净增量分别验证。使用可用agent-blind-eval设计对照、eval-result-analysis分析已有结果；缺失时沿宿主原评测方法。

先检查任务难度与材料是否会让强基线轻易全部通过。选择真实、互补的风险，包含确认缺陷、正确改动和批准取舍。固定输入版本、输出协议和评分依据，再执行；新难度题另开批次，保留旧题及原结果。

观察关键漏项、误报、条件/反例覆盖、证据与严重度是否正确、实际阅读/技能消费、人工修复、耗时和全流程成本。重复生成时两组同次数，至少各3次；多个重复输出与独立任务数分别统计。实际任务上的一次审计可证明完成了对应检查，其相对增量需同对象、同时间版本的原流程结果作依据。

遇到全部策略满分时，将结果解释为该样本无法区分收益。采用可以基于低风险、可回退和潜在收益，但效果保持待积累。评测开销本身计入净成本，达到宿主投入或失败停止条件后交用户决定。

GameFeel Bench的公开反向评估描述是本方法的启发之一。本Skill为工作区原创方法，组合已有审计经验与专业入口。原版未公开任务、答案或评分器的可用性与许可需独立核验，当前方法和本地验证不宣称复现完整Benchmark。[公开说明](https://github.com/kodasdream/gamefeel-benchmark/blob/c1e14546951ce9bfc91c59bf7a1bfcf170cbe3f6/README.md)
