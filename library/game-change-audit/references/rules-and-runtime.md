# 规则与运行审查

从批准规格和正常输入进入，沿预览、校验、执行、结算、持久化及反馈追一条完整路径。检查实际适用的面。

| 面 | 典型区分条件 |
|---|---|
| 合法性与支付 | 同一前置状态的预览与执行一致，支付/退款只发生应有次数，失败保留原状态 |
| 时序与身份 | 同名不同对象、目标移位/死亡、异步完成、跨回合与已锁定价格/目标仍正确 |
| 数值与构筑 | 基础值、取整、叠加顺序、上限、成本收益、资源循环和特定卡牌/修饰器例外 |
| 运行边界 | 重试、快速重复输入、取消/恢复、暂停、场景退出、旧回调、输入与坐标转换 |
| 存档与联机 | 旧数据、部分失败、重放/去重、权威状态、隐藏信息和顺序承诺 |
| 反馈与可读性 | 真实结果、预览、资源数值、输入提示与音画反馈表达相同状态 |

先复用宿主测试与重放，保全原存档，用实验副本验证假设。直接修改内部状态只能支持局部诊断，正常入口的结论另行验证。对余额、阈值、次序或身份相关问题补一个相邻正确条件，避免把设计取舍误报为缺陷。

平衡和乐趣判断需要代表性玩法、样本和明确目标。单个可利用循环可以证实机制存在，其普遍性和实际体验影响按实测范围说明。性能判断记录环境、负载、窗口与资源数据。
