# 游戏介绍写作

## 先定交付场景

- **Steam 商店页**面向准备了解、收藏或试玩的玩家。按游戏自身的类型、体验和有证据的区别决定语言、口气和篇幅；需要写或核对 Steam 字段时读[Steam 页面字段](references/steam-store.md)。
- **游戏详情、试玩入口或其他玩家渠道**按实际版位决定读者此刻需要知道什么。试玩页先让读者知道这版能玩什么、从哪里开始；篇幅允许时再展开玩法以及必要的背景。
- **个人作品集**沿宿主现有的作者口吻、选材和作品页方法组织，只在游戏玩法段借用下文；没有作者专项Skill时直接使用本次作者和读者要求。

已有介绍只需校字或语气调整时沿原编辑路径。规格、技术交接和非游戏作品沿其原入口。

## 从一个玩家决定写起

1. **核对事实。** 从项目确认的规则、目标试玩或发行构建与验收材料确认玩家、目标、代表性选择、可见结果和它怎样影响后续。背景只写能解释当前处境、目标或行动意义的部分。已交付、当前可试玩、历史原型和计划分别写清。每个渠道使用该渠道指向的实际版本。
2. **写短介绍。** 从类型、角色、目标中选一两个最能定位作品的信息，再给一个能让读者预见玩法的决定。例如骰子策略游戏可以用「继续深入，还是趁还能撤离时带走战利品」说清取舍，前提是当前规则支持。单步数字或术语只有在读者能凭它区分作品时才提前出现。
3. **写正文开头。** 让读者能复述一轮行动和它如何改变下一步。策略玩法写出选择、收益和代价；探索可以写目的地、沿途可走的路及其后果。用必要背景把动作接起来。保留各段独有的信息，正文按读者接下来要理解的玩法要点展开，具体局面和数字放到需要解释的位置。
4. **按需要把文字配到实机。** 截图适合显示局面、对象、路线和 HUD。短片适合展示动作发生前、触发和结果。为关键承诺核对素材来源、版本和可见证据，标明历史、示意或原型身份。已有媒体足够时复用，其他制作、网页接入和发布沿宿主的实际授权。

## 交稿前核对

单读短介绍，检查是否说得出这是什么游戏和一个代表性选择；单读正文开头，检查是否说得出一轮行动、结果及下一步。逐项对照目标构建核功能、条件、归属和可用状态。跨渠道复用已核实的事实，按读者目的重排信息和语气。中文成稿合并用 `humanizer-zh` 与宿主适用的 `anti-defensive-writing` 审校一次；读者确实需要术语转译时加入 `plain-language-zh`，在同一次编辑中保留原有规则与准确术语。
