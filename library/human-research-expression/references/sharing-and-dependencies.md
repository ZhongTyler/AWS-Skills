# 单文件交付与资源依赖

## 先确定分享范围

把交付物分成三层，按用户需要选择并说明实际覆盖。

1. 阅读成品包含正文、必要图例、交互、字体与样式。用户要求单份 HTML 时，将理解主线所需内容放入成品，图片按原字节内嵌，样式与脚本随页提供。保留来源、日期、条件和未知。
2. 内嵌附件可承载完整学习记录、参数说明等补充材料。附件正文进入 HTML 后，正文中的相对链接仍按原文件位置解释。下载附件不会自动带走这些被引用文件。
3. 证据档案包括未展示的原图、其他轮次输出、执行 JSON、原始音视频、脚本与工作流。只有用户要求独立核查或复现时，才按范围整理额外交付包，并检查授权、体积与私人路径。不要递归复制整个工作区。

主线理解依赖的内容应进入阅读成品。进一步核查需要的证据可以单独提供，并在来源区写清用途。使用“下载学习记录正文”等准确标签。单文件可阅读、附件正文完整、证据档案齐全分别判断。

## 复用现有制作入口

先从阅读问题建立概念依赖、全景关系与具体案例，再使用现有文字主本及渲染器。沿用目录、返回正文、图片观察与移动阅读组件。主题专用图解继续跟随本题解释，不把一份报告的章节数、外观或交互数量变成通用要求。

`render_report.py`、`render_visual_html.py` 和 `assemble_html.py` 的构建回执包含静态依赖摘要。已有独立成品可以直接运行审计器。

```text
python scripts/audit_html_dependencies.py report/index.html --output audit.json --check-runtime
```

要审计内嵌 Markdown 的进一步引用，显式提供附件原位置映射及允许检查的目录。映射中的 SHA-256 必须与内嵌附件原始字节一致，避免拿另一版材料推定引用状态。

```json
[
  {
    "download": "lesson-learning.md",
    "path": "/absolute/research/lesson/README.md",
    "sha256": "sha256-of-embedded-markdown-bytes"
  }
]
```

```text
python scripts/audit_html_dependencies.py report/index.html --attachment-origins origins.json --allow-root /absolute/research --output audit.json --check-runtime
```

工具只读取成品并检查允许目录中的文件是否存在，不访问网络、不执行页面脚本、不递归读取证据正文，也不自动打包。不要为定位一个链接扩大允许目录。

## 三种引用分别核对

- 运行资源包括图片、样式、脚本、字体、媒体和内嵌页面。CSS URL、srcset、SVG 引用也要核对。相对文件在原机存在，仍然属于单文件之外的资源。
- 普通来源链接用于打开外站或其他文档。外站链接需要网络。必要解释应在成品中自足。
- 附件里的进一步引用按每份原附件的目录解析，去掉锚点后按实际目标文件去重。同时列出链接出现次数、独立目标数、已在别处内嵌的 Markdown、工作区存在、工作区缺失及无法确认的目标。已内嵌的另一份正文，其下载后原相对链接也可能需要重新定位。

公开交付前审查清单中的私人绝对路径、内部记录和文件名。HTML 使用依赖审计摘要时，避免把包含该 HTML 哈希的完整审计再次嵌入自身，造成循环身份。

## 验证与交付说明

静态审计覆盖 HTML/CSS 与常见 Markdown 链接。脚本动态构造资源、内嵌页面、特殊 Markdown 写法和运行期网络访问需要另外检查。`--check-runtime` 只对静态运行资源的外部依赖报错，附件中的证据引用单独报告。存在动态 API 提示时读相关脚本，并在浏览器验证实际请求。

按 [阅读层维护](reader-maintenance.md#localhost主验收与本地文件简查) 验证同一成品的实际阅读。记录成品哈希、访问方式、桌面与窄屏、目录与来源返回、图像观察、键盘及附件下载的实际覆盖。工具不支持的访问方式保留未验证状态，遵守已有工具限制。页面通过与目标读者理解分别记录。

交付时简要说明分享哪些文件、外站是否需联网、附件进一步引用是否齐全，以及这些边界影响通读、深入查证还是复现。更改分享标签或说明时先改文字主本，再生成 HTML，复核受影响段落和链接，复用未变的有效证据。
