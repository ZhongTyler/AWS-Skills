# 完整游戏项目详情

沿 [Skill 入口](../SKILL.md) 选材后，把完整详情的关键关系安排进图文。可借鉴游戏或桌游众筹详情的图文讲解，筹款信息沿原渠道。

## 玩法从整局全景走到关键节点

1. 先用规则、实际构建和可展示材料列提纲。玩法正文先给整局全景，交代玩家的目标、起点、反复经历的行动单位、如何推进和结算、何时结束。有多个尺度时，写清一次行动、回合、房间或关卡的结果怎样带到上一级或下一段。只需一条线时沿它讲完整。
2. 再按影响核心选择或后续局面的关键节点分节。让读者先认出能操作的对象、动作发生的位置和结果出现的地方。用游戏实际的对象、动作和变化命名小节，给关键判断配事实和必要图证。完整规则表和数值按需下钻。
3. 资源或状态变化驱动玩法时，分别讲清**行动流程**和**资源流转**。行动写玩家可以做什么、按什么条件推进、在哪结算。资源或状态写从哪来、在哪投入、增减或转移、哪些会保留或丢失、带到下一段后改变什么。两条线在同一批节点交汇且合图更清楚时，用共享节点标出行动与变动各自的走向。

## 选一到少量局面，把过程走完

- **起始画面。** 标出该局面可见的关键对象、位置、资源或状态，以及当时要完成的事。为不熟悉规则的读者补足理解接下来动作所需的条件。
- **选择与结果。** 有实际取舍时，在同一条件下说明至少两种有意义的做法、适用条件和代价。讲清实际采用的动作、反馈和结算结果，以及它们怎样影响下一步。另一条路径仅由规则得出时标为「规则推演」，设计记录中的假设盘面标为「设计示例」。以观察或操作为主、缺少明确分支的游戏，沿已发生的变化及其触发条件写。
- **图文分工。** 空间与对象用带标注的实机图或桌面图，动作和时序用前后关键帧或短片，分支条件用短表。正文保留规则条件与因果。标注构建身份，核对图中对象、动作、结果与文字一致。示意图写明依据与身份。缺少画面时可用有来源的文字或表格，并说明缺少哪段画面。素材权限和可见细节按项目确认。

## 设计写决定核心体验的机制

把形成体验的条件、代价和后果放在同一局面里讲。有实际方案对照时，对齐起始条件，标出各方案改变了哪条规则和什么结果。图注标明图来自原型、实机还是规则推演，正文交代作者决定、观察样本或推断的依据。

## 制作从成品的长处往回追

把成品画面和能解释它的过程材料放在一起。用原型或改前画面指出具体问题，用过程图、关键帧或短片标出制作选择改变了哪里，再让读者在同版成品里找到结果。跨版对照各标版本与可操作范围。技术细节展开到足以解释可见变化，测试和验收记录放在对应主张旁作佐证。

## 整页验收

- **玩法。** 陌生读者能复述整局目标、推进与终点，再从代表局面的起始条件讲到行动、反馈、结算和下一步。有取舍时能说出两条路的差别。资源或状态驱动玩法时，能追到它从哪来、结算后去哪、如何影响后续选择。
- **设计。** 读者能指出哪些规则共同塑造了核心体验，说明结构与体验的因果关系，并分辨项目决定、实测发现和规则推断。
- **制作。** 读者能指出成品中的一处长处，追到对应的制作选择与过程，核对版本和成品证据，并说出验证覆盖到哪。
- 逐项核对玩法、图证、试玩入口与引用。关键条件只在图里时，在实际版面核对其可读性。只能复述类型和一个选择时，按首页卡片深度看待，并回提纲补足完整详情缺失的环节。素材缺口按实际来源说明。
