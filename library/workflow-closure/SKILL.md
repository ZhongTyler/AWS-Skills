# 工作流收尾
用户要求收尾、提交、完成并提交或暂停交接，或已授权任务进入最终闭合阶段时使用。普通进度问答不启动写入式收尾。
先读宿主当前README、AGENTS和实际交付合同。没有专用手册时按当前授权、真实成果和以下最小闭合方法执行，不假定meta、AWS、编排器或私人目录存在。合同冲突或下一动作确实缺授权时保留停点；方法不授予发布、外发、删除或付费权限。
1. 核对目标仓、当前分支、已有dirty/index和并行owner，只处理本任务。明确实现、运行、正式采用、发布和人工验收分别由什么证据支持。
2. 跑受影响行为及必要失败／恢复路径，检查实际退出码。输入未变且仍覆盖目标的证据可复用。异步任务按当前对象身份等终态，不以启动成功或旧记录代替本次完成。
3. 只更新因本次变化而失真的规格、引用、状态和用法。有可迁移原则、纠正或反例时交实际owner，普通流水不强制创建观察。术语、路径、版本或接口变化按[知识面核对](references/knowledge-consistency.md)追踪原权威与消费者；复杂交付可用[可审查的变更](references/reviewable-change.md)。
4. 先判断变化是否影响已公开包，再判断网站展示是否失真。固定发布快照按当时版本解释；新方法可列候选，不自动发布或宣称上线。公开独立模块沿该仓当前发布合同，历史输入和tag保留。私人内容不进入公开材料。
5. 每个改动仓形成范围明确的提交，按宿主合同集成实际主干并验证结果。存在子仓时，每个直接父仓提交匹配gitlink直到目标最外层。宿主有检查器时复用；没有时核对真实提交树和父边，明确未执行机器检查。推送沿当前授权和例外，不推无关分叉历史，不以本地提交冒充送达。
6. 保留失败、恢复点及仍需决定的事项。临时分支／工作树在归属、数据和恢复依赖清楚且授权允许时清理，否则说明保留原因。暂停或换会话时可用已配置session-handoff或宿主原交接入口，保存版本、owner、停点和下一动作，不另建状态源。
最终据实报告实现验证、提交集成、父边、推送、清理、对外更新和人工验收；未完成项保留具体状态。工程PASS不升级为真实使用、体验认可或长期收益。
