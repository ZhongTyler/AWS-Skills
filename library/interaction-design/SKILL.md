# 界面交互设计

当前任务涉及界面状态变化、操作反馈或交互控制时，读取[交互方法](references/interaction-method.md)，只采用与真实问题相关的部分。先确定动作、实际状态和要解决的定位／理解／控制问题，再选择效果；不要求集齐效果或建立工作台。

需要选择控件或具体做法时，按问题读取[交互配方](references/interaction-patterns.md)的对应主题：反馈状态、选择/输入、导航/弹层、对象转场、手势控制、就地操作、可操作图表、多视图事件图或动效表达。先比较任务适配和操作成本，再选配方；已有“连续性”等原则不能代替具体选型。普通单处修复只读命中部分，不遍历全部案例。

界面说明重复、精简文案或决定常驻／按需帮助时，读取[界面文案与信息显露](references/interface-copy.md)。网页、App、工具面板和游戏UI共用同一分类方法；纯文案问题可只读该页，不额外加载动效配方。

沿宿主已有规格与QA实现，核对同一对象的身份、选择与焦点，快速重复／反向操作、取消与恢复，以及实际支持的输入和减少运动。方法说明不能代替真实运行；复用输入未变且覆盖仍有效的验证，新增行为验证受影响部分。


游戏或工具面板需复现状态并验证重绘后的完整操作时，按需读取[生产状态验证](references/production-state-validation.md)。复用宿主生产渲染入口，验证选择、继续导航、提交/取消、返回与下载；已有样例覆盖的状态沿原记录复用。

需要明确动效名称、比较动态示例或取得具体参数时，按需使用可发现的`motion-prompt`。用户给编号／选项时按原顺序读取；Agent自行执行时先查窄分类，回宿主实现真实状态与操作。入口不可用时沿现有方法，小修不额外打开图库。

网页视觉方向由frontend-design或宿主设计规范负责；游戏资产、音画及引擎交付由GamePresentation或宿主流程负责，不因调用本Skill反向加载整套流程。业务规则、合法落点、存档与体验接受仍由宿主拥有。

复杂配置、多步提交、依赖权限或可复用组件的状态仍有具体缺口时，沿宿主现有界面设计入口 选择已登记的原版专项参考；只读命中部分。宿主入口或原件不可用时继续本方法，普通单处修复不额外加载专项。

游戏引擎菜单/HUD的焦点、缩放、安全区、数值更新或返回流需要具体配方时，按需调用 `game-ui-ux`；未发现或未配置时继续本方法与宿主引擎规范。保留宿主布局与输入承诺，不为小修强制菜单栈；视觉打击反馈另按GamePresentation选择 `game-feel`，普通网页不全量加载游戏配方。

游戏HUD拥挤、信息显露/通知、改绑提示、伤害数字、径向菜单、冷却或小地图需要选型时，读[游戏界面配方](references/game-ui-patterns.md)的命中部分；同时补最长数值与实际状态×目标视口检查。引擎焦点/缩放沿game-ui-ux，纯样式不遍历全部配方。

资源变化要跨界面区域解释来源、去向和到账时机时，读[跨区资源反馈](references/game-ui-patterns.md#跨区资源反馈)。主区域被状态变化挤动，或局部滚动影响反馈与焦点可见性时，读[主区域稳定与局部滚动](references/game-ui-patterns.md#主区域稳定与局部滚动)。多个动作需要逐项评审时，读[逐动作评审样例](references/game-ui-patterns.md#逐动作评审样例)。

结果回宿主已有记录，区分实现、操作验证、用户体验与长期成本。只有观察／调参／复现本身形成瓶颈时，才组合可用的feedback-loop或现有诊断入口；普通静态排版不强制加载本Skill。Skill不可发现时，调用方可读取本目录入口，不猜测另一份方法或自动启动其他Agent、MCP和服务。
